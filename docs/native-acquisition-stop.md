# Native acquisition stop proof

This is a declared SDK conformance check with no models. It is separate from an
intelligence, Survival or competitive trial. The operator owns every actor and
runs the commands; preparing this protocol or its Rust transport fixtures does
not execute gameplay.

Use a dedicated character and an existing connected controller/body session.
Keep its normal permissions, natural terrain and protective body. Do not change
an evaluated actor's inventory, position, health, world or code to make this pass.
No operator items, item summons, teleports, healing, rollbacks or mob removal.
Record setup and all attempts, including lack of a suitable held-input overlap.

1. Record immutable source, controller/SDK binary, config/profile hashes, server
   instance, UUID, life, dimension and native sample epoch. Keep keys private.
   Record empty initial inventory, cursor/personal grid and saved state.
2. Through ordinary non-operator SDK mining and pickup, earn two logs with one
   observed runtime item ID. Keep original native receipts/statistics. Mine the
   third naturally but remain outside pickup range. Declare the exact registry
   ID and total retained target3 before starting navigation. These supplied
   mechanics are an assist and do not establish autonomous acquisition.
3. Choose a previously observed, natively admitted reachable goal beyond the
   drop on an unchanged natural path. Freeze the goal and options below. The
   approach must allow pickup while one saved movement is still Running. Do not
   move an item, edit terrain or alter input duration through operator controls.
4. Use a new private journal and bounded capture. Run the existing CLI inside
   the owned isolated controller environment, inheriting its body arbiter:

   ```text
   mc-sdk navigate PRIVATE_PROFILE GOAL.json NEW_JOURNAL.json OPTIONS.json
   ```

   Opt-in options (replace `runtime:log` with the declared actual ID):

   ```json
   {"timeout_ms":10000,"max_steps":16,"max_nodes":128,"eager_progress":false,"until_inventory":{"item":"runtime:log","minimum":3}}
   ```

5. Preserve original trusted action rows and observations, not only CLI stdout.
   The count-confirming sample in `inventory_cancellation` must match the saved
   movement's UUID/life/dimension/epoch, show3 retained logs, and bind the exact
   active Running control. Require native evidence of frames sent; a prepared
   job or cursor/menu count is not the declared overlap.
6. Inspect both IDs using the existing CLI:

   ```text
   mc-sdk status PRIVATE_PROFILE ORIGINAL_MOVEMENT_ID
   mc-sdk status PRIVATE_PROFILE CANCELLATION_ID
   mc-sdk query PRIVATE_PROFILE FRESH_QUERY.json
   ```

   `FRESH_QUERY.json` contains
   `{"capability":"minecraft:fresh_observation","input":{}}`.
   Require exactly one cancellation intention/dispatch, with its payload
   `cancel_control.action_id` equal to that original movement ID. Require the
   cancellation receipt to be native Observed, not a local pre-dispatch
   rejection, and the original movement to remain Cancelled with released
   input. Do not relabel it Observed. No new movement may follow fulfillment.
7. Require `inventory_satisfied`, no pending input, a still-positive positional
   gap, and an independent fresh same-life retained count3. Save normally and
   independently confirm retention. Record damage/deaths and any body takeover.
   A naturally finished movement, foreign-control cancellation or fulfilled
   count first seen after release cannot establish the held-input cancel case.

Predeclare a1000ms upper bound from the helper's first **fresh confirmed** count
sample to an independent native sample proving original input release. Match
sample epochs and use native monotonic clocks. This includes verification delay;
it is not a measurement from an unobserved physical pickup instant. Preserve all
latencies and failures rather than changing the bound afterward.

For contrast, repeat once with separately declared naturally earned resources
and a new journal, omitting `until_inventory` entirely. Keep the same reachable
approach design and budgets. Require a witnessed2→3 pickup during Running input,
zero acquisition cancellations, and normal positional completion. Do not reuse
an old inventory condition, inject a third log, or treat a timeout as a pass.
Disclose differing terrain and drop motion; this is a semantic contrast, not a
matched speed benchmark.

A second invocation after a lost reply must inspect/reconcile the saved cancel
ID. It must never resend that cancellation or the original move. Preserve both
IDs and any uncertainty; input release and item retention cannot manufacture a
verified historical effect. The source fixtures cover this interruption branch;
no live network fault is required for the basic native proof.

Pending evidence remains pending until these actual native observations exist.
The earlier quiet crafting pilot did not opt into this condition and cannot
retroactively satisfy this proof.
