## Bounded evidence without prefix omissions

Combined capture requires the matching pristine baseline beside the original
handler trace. It selects **every action row for that actor**, including generated
program prefixes, and verifies its row count against the same SQLite transaction.
Body-only trace intention equality is not asserted for generated-program actions.
Original traces, fatal lines and every rejected/running/uncertain outcome remain.

| Input/output | Combined bound |
| --- | --- |
| Handler stdout and stderr |128MiB each, explicit overflow status and failed child |
| Original trace / aggregate row intent+receipt bytes |128MiB each |
| Native action rows |32768; overflow fails instead of selecting a subset |
| Native report shard |128 actions,6MiB input budget,8MiB final maximum |
| All native reports |512MiB maximum |
| Required disk headroom |2GB above the500GB reserve, with report-write checks |

Legacy stream/capture bounds remain16MiB and4096 rows. The8MiB compressed workspace
archive and64MiB retained pinned-binary bounds remain unchanged. An oversized
archive is incomplete and retains the proven idle container for recovery; it is
not silently widened or called a complete export. A stream overflow, missing or
old stream status, row/byte/report limit, or missing baseline blocks complete
evidence. Keep the entire authoritative journal and partial private files for
bounded recovery; never discard outcomes, trim a failed arm into a passing one,
or replace original failed evidence.

Complete combined capture requires the original stdout, stderr and status sidecars.
The status must explicitly report no stream overflow and its stdout/stderr hashes
must match the exact supplied files. A stale status cannot authenticate a replaced
or truncated trace; missing or mismatched sidecars remain incomplete.
